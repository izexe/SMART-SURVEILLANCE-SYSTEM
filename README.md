# Smart Audio Surveillance System

A software-based environmental sound classification project combining
**Digital Signal Processing (DSP)** and **Machine Learning**. It
captures audio through a computer microphone, classifies it into six
sound categories, displays results in a Tkinter GUI, and generates
alerts for selected sounds.

## Features

-   Live audio capture from a laptop or external microphone.
-   Sampling rate: **22,050 Hz**.
-   Audio processing in **5-second blocks**.
-   Six sound categories: door knocking, glass breaking, alarm/siren,
    dog barking, footsteps, and background noise.
-   **32 extracted features** using MFCC, spectral centroid,
    zero-crossing rate (ZCR), and spectral rolloff.
-   SVM classifier with an RBF kernel.
-   GUI showing predictions and estimated confidence.
-   Audible alert for `glass_breaking` or `alarm_siren` when estimated
    confidence is at least **65%**.

> **Disclaimer:** This is an educational prototype. Predictions may be
> wrong, particularly in noisy or unfamiliar environments. Do not rely
> on it as a replacement for a professional security or emergency-alert
> system.

## How It Works

1.  Capture audio through a microphone.
2.  Process the audio and extract DSP features.
3.  Calculate the mean and standard deviation of the features to create
    a 32-dimensional vector.
4.  Pass the vector to a trained Support Vector Machine (SVM).
5.  Display the predicted class and estimated confidence in the GUI.
6.  Generate an audible alert when the configured target class and
    confidence threshold are met.

## Installation

### 1. Clone or download the repository

``` bash
git clone https://github.com/izexe/SMART-SURVEILLANCE-SYSTEM.git
cd SMART-SURVEILLANCE-SYSTEM
```

You can also download the repository as a ZIP file from GitHub and
extract it.

### 2. Create a virtual environment (recommended)

On Windows:

``` bash
py -m venv .venv
.venv\Scripts\activate
```

### 3. Install dependencies

If `requirements.txt` is present:

``` bash
py -m pip install -r requirements.txt
```

Otherwise, install the core packages:

``` bash
py -m pip install numpy scipy matplotlib librosa soundfile scikit-learn joblib sounddevice
```

Tkinter is included with many standard Windows Python installations.
`winsound` is Windows-specific; adapt the alert code if running on
another operating system.

## Dataset and Training

The project uses selected categories from the ESC-50 dataset and can
include additional labelled microphone recordings.

1.  Download and extract the ESC-50 dataset.
2.  Place the audio files and metadata where the dataset-preparation
    script expects them.
3.  Run the dataset-preparation script if required.
4.  Use `record_training.py` to record additional samples and save them
    under the correct category.
5.  Train the model:

``` bash
py train_model.py
```

The training script prepares feature vectors, trains the SVM, evaluates
it using the configured test split, and saves `sound_classifier.pkl`.

**Evaluation note:** Accuracy on the ESC-50 test split does not
necessarily represent performance on new live microphone recordings. Use
separate, unseen recordings to evaluate real-world performance.

## Running the Application

Launch the GUI:

``` bash
py gui.py
```

Or run live detection from the terminal:

``` bash
py live_detect.py
```

For file-based prediction, follow the usage supported by
`predict_sound.py` in the current source code.

Make sure `sound_classifier.pkl` exists at the path expected by the
selected script. Allow microphone access if prompted. Detection runs on
five-second blocks and is not instantaneous.

## Feature Extraction

The system calculates:

-   **13 MFCCs:** mean and standard deviation of each = 26 features.
-   **Spectral centroid:** mean and standard deviation = 2 features.
-   **Zero-crossing rate:** mean and standard deviation = 2 features.
-   **Spectral rolloff:** mean and standard deviation = 2 features.

**Total: 32 features per audio block.**

The features are standardized using `StandardScaler` and passed to an
SVM with an RBF kernel. Estimated class probabilities are used to
display confidence and apply the alert threshold.

## Alert Logic

An audible alert is generated when:

1.  The predicted class is `glass_breaking` or `alarm_siren`; and
2.  Estimated confidence is **65% or higher**.

This is a configurable threshold, not a guarantee that the prediction is
correct.

## Troubleshooting

-   **No microphone audio:** Check microphone permissions and the
    selected input device.
-   **Missing package:** Activate the virtual environment and install
    dependencies.
-   **Model file not found:** Run model training and check that
    `sound_classifier.pkl` is in the expected location.
-   **Unexpected predictions:** Try cleaner recordings and add varied,
    correctly labelled training samples. Background noise, recording
    distance, and differences between training and live audio can affect
    results.
-   **GUI appears unresponsive:** Check that audio processing is handled
    in the background as intended.

## Limitations and Future Improvements

-   Classification operates on five-second blocks.
-   Background noise and overlapping sounds can reduce accuracy.
-   Unfamiliar sounds may be assigned to one of the six known classes.
-   Confidence values are estimates and may not be perfectly calibrated.
-   Future work could include more varied microphone data, testing on
    unseen real-world recordings, threshold tuning, and lower detection
    latency.
